# 库存查询与出库契约

## 输入

- 订单中心出库以中央 SQLite 中已保存的订单、材料、工厂单和五金事实为唯一业务输入，不要求存在或读取 Traveler。
- 订单材料事实与出库范围分开保存：来料加工订单可以明确标记“客户提供，不出库”，材料和封边仍保留在 `material_items`，但不进入出库单；只有工厂单五金仍需要出库时，五金照常生成对应出库单。
- 客户提供材料且所选工厂单没有有效五金时，继续使用订单出库界面的确认动作，但只更新订单索引 SQLite：工厂单统一标记“已出库”，`outbound_mode=customer_supplied`，不创建库存系统出库单；材料事实指纹变化后状态回到“需要更新”。
- 来料加工订单只要存在本公司需要出库的材料或有效五金，就按真实库存出库流程处理；系统可以自动选择路径，但真实库存写入仍须经过出库界面的最终确认。
- “余料生产，不出库”必须由用户在订单中心明确确认并填写原因；数据库没有材料或五金时永远不能自动推断为余料生产。
- 订单级材料从 SQLite 的材料事实汇总；所选工厂单的五金从 SQLite 的工厂单事实读取。
- 独立 Traveler 出库入口仍兼容规范 Traveler，但它是历史/人工文件入口，不参与订单中心新流程。
- 数量为负数或非数字时停止。数量为 0 的项目保留在机器可读诊断中，但不显示为出库预览行，也不写入。

## 查询

1. 优先复用由 App 打开的库存专用 Chrome 中已经登录的 `jdy.com` 及其子域名工作台页面（包括按租户或区域跳转的地址，如 `vip2-hz.jdy.com/default-new.jsp`）；登录入口使用 `https://www.jdy.com/login/`。复用时不再次登录，也不读取库存系统钥匙串密码。没有可复用页面时，才进入原有 Playwright 登录流程。
2. 进入“仓库 → 商品库存余额表”。
3. 输入 SKU 并选中唯一商品候选，仓库留空。
4. 表格无内容即数量 0。
5. 默认查板材和封边，五金仅在设置或本次请求启用时查询。

## 预览

每行显示 SKU、订单材料名称、库存商品名、需求数量、可用数量、匹配来源和警告。板材/封边预览按订单，五金预览按所选工厂单。从订单中心选择一个或多个工厂单出库时，出库窗口只显示订单级板材/封边与所选工厂单五金，不显示左侧 Traveler 文件列表；预览直接校验数据库事实、商品映射和数量。不校验跨系统单位字符串。

## 审批与写入

- 映射缺失是阻断错误；库存不足是允许继续的警告。
- 映射与忽略只在订单文件读取/Traveler 读取阶段处理；订单中心出库窗口改为“数据预检”，只展示数据库事实、出库范围和异常，不提供映射、忽略或模拟填写按钮。
- 标准工厂单出库前先按准确工厂单号读取订单索引 SQLite；若 `outbound_status` 已为“已出库”且当前数据库事实未变化，出库按钮必须禁用，后端也必须拒绝本次写入。
- 如果订单数据库中当前材料或五金事实相对上次成功出库记录发生变化，状态变为“需要更新”；用户明确确认后才允许编辑原出库单。更新成功后必须同步写回库存同步记录、订单索引 SQLite 的工厂单出库状态/单据号/更新时间，以及当前数据库事实指纹。内容未变化时不得重复打开保存流程；查不到原出库单时停止并要求人工核实，不能自动新增。
- 封边在 material 解析阶段已经按 Excel 显示值取整；库存出库直接使用本地业务事实中的显示整数，不再保留小数。
- 写入前再次校验数据库订单事实指纹和商品映射指纹；独立 Traveler 入口才校验 Traveler 指纹。
- 板材和封边的出库单备注为订单号；五金的出库单备注为工厂单名称。
- 点击保存后必须按单据号回查。结果不确定时不自动重试写入。
- 订单数据库数量减少时，更新原单据；原单据不可编辑时停止并提醒人工处理。独立 Traveler 入口按 Traveler 数量执行同样规则。
- 出库自动化不把当前 Chrome 停留的页面当作本次出库页面：先等待库存业务工作台和左侧菜单可用，再进入其他出库单记录列表，按备注查重后打开旧单或全新的新增表单。
- 当前页面可能残留上一次操作的表单内容；这些内容不直接复用。保存前必须回读全部非空材料行，商品编号、数量和行数必须与本次 Traveler 完全一致，发现额外行或不一致时停止保存。
- 临时订单的板材和五金可以一起出库；出库单备注使用临时文件夹名称。临时订单没有标准工厂单号时，不得因此阻止出库。
- 用户关闭“出库包含五金件”后，生成或更新 Traveler 不写入五金，出库只读取最终 Traveler，不再从 Fittingslist 等源报表额外补出五金。
- 全局忽略的五金不写入中央 SQLite；历史残留由忽略动作清理，数据库出库预览和订单详情仍按忽略清单兜底过滤，不能出库。
- 订单事实入库前必须完成商品资料 SKU 匹配、有效人工映射或全局忽略；未解析项目阻止本次订单事实替换，并保留现有事实供后续处理。AICNC `WJ-*` 来源编码仅用于来源/显示追溯，不直接作为库存 SKU。
- 材料映射和全局忽略规则统一从中央 `workflow.sqlite3` 读取；保存时保留原始显示名称，标准化名称只用于跨订单匹配。旧 `mappings.json` 只执行一次数据库迁移，成功后不再作为运行时来源。
- 临时订单出库失败后重试：如果源报表指纹、Traveler 生成时的五金选项、Traveler 状态和 Traveler 文件均未变化，则复用已有 Traveler；否则重新生成或更新后再出库。
- 出库成功必须同时保留库存同步记录和临时订单台账；台账按稳定文件夹身份记录处理状态、出库状态和单据号，防止重复出库。
- 库存同步记录保存在当前运行范围的 `state_dir/inventory-outbound-records.json`；标准订单出库成功后必须同步回订单索引 SQLite 的工厂单出库状态，临时订单还要同步临时订单台账。重新打开 App 时先用该记录恢复出库状态。
- 中央 SQLite 的 `outbound_documents` 保存每张库存出库单一次；一张单据覆盖多个标准工厂单时，必须在 `outbound_document_factories` 中为每个工厂单保存独立关联。索引刷新和对账读取这些关联，不得把组合工厂单字符串当作单一工厂单身份。

## 本地记录

保存数据库事实指纹、预览快照、用户审批、出库单号、结果、差异和错误；独立 Traveler 入口另保存 Traveler 指纹。不保存密码、浏览器登录状态或完整 Traveler 历史副本。验证码、滑块、安全验证或登录失效时暂停自动化，由用户在库存专用 Chrome 中完成验证；不得绕过库存系统安全验证。普通用户直接启动、没有 CDP 端口的 Chrome 不由 App 强行接管。
