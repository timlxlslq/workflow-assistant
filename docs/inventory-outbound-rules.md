# 库存出库业务逻辑与流程

> 状态：讨论稿，业务规则已确认，等待用户最终审核后实施。  
> 范围：读取 Work Order Traveler 的 Pickinglist，并在金蝶精斗云库存系统中创建或更新“其他出库单”。  
> 安全边界：所有任务均由用户手工启动；正式保存前必须人工确认；测试时绝不点击保存。

## 1. 功能目标

现有功能负责从 AICNC 报表生成 Traveler，并计算每个订单使用的板材、封边和五金。新增功能负责：

1. 扫描订单目录中的 Traveler。
2. 由用户手工选择需要出库的文件。
3. 读取 Pickinglist 全部区域的有效领料项目。
4. 使用本地商品主数据将 Traveler 名称映射到库存商品编号。
5. 在金蝶精斗云中创建或更新“其他出库单”。
6. 记录每份 Traveler 的出库状态、单据编号和最后同步结果。

## 2. 用户操作入口

库存出库使用独立页面，配置中心保留商品资料和映射管理。

### 2.1 Traveler 列表

按 PP 订单文件夹分组显示：

| 字段 | 说明 |
| --- | --- |
| PP 文件夹 | Traveler 所在订单文件夹 |
| Traveler 文件 | 完整文件名 |
| 工厂单名称 | Traveler 表内正式工厂单名称 |
| 修改时间 | 当前文件最后修改时间 |
| 出库状态 | 未出库、已出库、需要更新等 |
| 单据编号 | 已关联的库存出库单号 |
| 最后同步 | 最后一次成功或失败时间 |
| 异常摘要 | 当前阻止出库的问题 |

左侧不再提供“显示历史文件”开关。点击文件夹后显示该文件夹内的全部 Traveler；
已出库文件继续使用现有状态样式。每个文件夹标题右侧提供状态刷新按钮。
按钮必须实际登录库存系统，在“其他出库单记录”中按 PP 文件夹号查询备注，
再使用规范化后的正式工厂单名称建立唯一关联并写入本机同步记录；未找到或多条匹配时只提醒，
不得把已有状态降级，也不得猜测关联。
查询时不得沿用页面默认的“本月截至当天”范围。程序将日期范围设置为本机当天往前550天、
往后45天，以覆盖早期手工出库记录及中国服务器与本机时区跨日产生的未来一天单据号。
查询不到记录表示该 Traveler 当前没有可识别出库单，是正常状态，不显示“需要人工核实”。
只有匹配到多个候选单据号时才提示人工选择，并在操作记录中列出工厂单名称和候选单据号。
真实出库成功后必须显示醒目的绿色成功提示，并立即更新左侧 Traveler 为“已出库”。
打开库存出库页面时只扫描文件夹名、Traveler 文件名及已有本机同步状态，不打开或解析工作簿。
用户点击具体 Traveler 后才读取工作表、校验内容、检查数量并执行商品映射。

### 2.2 选择方式

- 从本次新生成或更新的 Traveler 列表中选择。
- 手工选择任意已有 Traveler `.xlsx` 文件。
- 左侧文件列表采用单文件点选：不显示复选框，点击文件后整行高亮，并立即在右侧自动预检和显示该文件的全部材料。
- 点击另一份文件会切换当前选择及预览；每份 Traveler 必须分别预览、分别确认、分别保存。
- 不允许无人确认的批量出库。

### 2.3 页面布局

页面重新排版为四个整齐区域：

1. Traveler 选择。
2. 检查与预览。
3. 网页执行状态。
4. 历史同步记录。

异常和差异使用表格显示，不用难以比较的长文本堆叠。

## 3. Traveler 读取与任务前置检查

必须先完成本地检查，确认无误后才打开库存系统。

### 3.1 工作表和表头

- 同时读取 `WorkOrderTraveler` 和 `Pickinglist`。
- 按表头文字识别字段，不固定单元格坐标。
- Pickinglist 必须能找到 `Name名字` 和 `QTY数量`。
- 表头改名、缺失、重复或名称与数量无法对应时停止，不猜测列位置。
- 两个工作表中的工厂单名称：
  - 一致：正常使用。
  - 一处为空：使用另一处，并在预览中提示。
  - 两处都有值但不一致：停止并提醒。
  - 两处都为空：停止。

### 3.2 读取范围

读取 Pickinglist 的全部区域，包括：

- Panel 板材、饰面板和封边。
- Fitting 配件。
- Hardware Accessory / Hardware 五金功能件。
- 将来出现的其他区域，只要有有效 `Name名字` 和数量，也纳入处理。

保持 Pickinglist 原始行顺序，不按名称或商品编号重新排序。

### 3.3 数量规则

| 数量情况 | 处理 |
| --- | --- |
| 正数 | 正常出库 |
| 0 | 跳过，不写入 |
| 空白 | 等同 0，跳过 |
| 负数 | 停止整张出库单并提醒 |
| 非数字 | 停止整张出库单并提醒 |

以后生成 Traveler 时，未使用但保留的材料行统一填写数字 `0`，不再留空。

数量直接使用 Pickinglist 原值，不做单位换算：

- 板材按 Traveler 数量。
- Traveler 继续保留封边两位小数；写入库存系统时封边米数按标准四舍五入取整，并在预览及操作记录中显示“原始米数→实际出库整数”。
- 五金按 Traveler 中的个数或套数。
- 库存系统自动带出什么单位就保留什么单位，程序只修改数量。

### 3.4 重复和冲突

- 同一 Traveler 中相同 `Name名字` 出现两次且数量均大于 0：停止，显示行号、区域和数量，由人工判断。
- 多个不同 Traveler 名称映射到同一商品编号：停止，显示名称、商品编号、数量、区域和来源，由人工判断。
- 缺少商品映射：停止整张出库单，一次列出全部缺失项。
- 零数量或空白项目不要求商品映射。
- 即使项目被标记为忽略，负数或非数字仍属于 Traveler 数据错误，必须停止。

## 4. 工厂单名称与出库单身份

- 库存出库单备注填写 Traveler 表内的正式工厂单名称。
- 一个工厂订单填写一个名称。
- 多个工厂订单合并时，以 `/` 分隔全部正式工厂单名称。
- 不使用 Traveler 文件名括号里的源文件夹名称代替正式工厂单名称。
- Traveler 本身不保存 `F...` 工厂单号，因此不能以工厂单号作为主键。
- 本地记录使用“工厂单名称组合＋Traveler 路径”联合追踪。
- 两份不同 Traveler 使用相同工厂单名称组合时停止并提醒。
- 同一路径中的工厂单名称发生变化时，显示新旧名称并要求人工确认是否仍为同一张出库单。
- 文件移动或改名且名称也发生变化时，必须人工关联原出库单。

## 5. 商品主数据

### 5.1 数据来源

商品资料由程序从金蝶自动导出：

1. 自动登录库存系统。
2. 点击左侧“商品”。
3. 在弹出菜单中继续点击“商品”。
4. 将鼠标移到菜单外空白区域。
5. 等待菜单消失。
6. 点击右上角“导出”。
7. 等待 `商品导出_*.xlsx` 下载完成。
8. 识别任务开始后新生成的下载文件。
9. 先校验必要结构，再替换当前商品主数据。

更新是配置中心的独立手工操作，不在每次出库前自动执行。

### 5.2 本地保存

- 程序内部使用固定文件名 `resources/inventory/current-products.xlsx`。
- 下载文件夹中的时间戳原文件保持不动，由用户自行清理。
- 程序不保存商品资料历史备份。
- 商品资料、真实映射、库存、采购价均只保存在本机，不上传 GitHub。
- GitHub 只保留字段说明或空白示例。
- 商品资料超过 30 天时提醒，但不阻止出库，也不提供修改提醒周期的设置项。

### 5.3 校验范围

- 导入时只确认文件可读取并包含必要表头。
- 不扫描或阻止无关商品的数据问题。
- 只有某个 Traveler 项目实际需要匹配时，才校验对应候选商品的编号、名称、规格、状态和冲突。
- 无关商品的类别异常、字段错误或编号重复不影响本次出库。
- 如果问题涉及当前需要查询的商品，则停止该 Traveler 并提醒。

## 6. 商品匹配

### 6.1 匹配方式

配置中心显示三种状态：

| 状态 | 说明 |
| --- | --- |
| 自动匹配 | 依据类别、名称、规格和已确认规则唯一找到商品 |
| 人工指定 | 自动匹配有歧义时，由用户从候选商品中选择一次并复用 |
| 忽略 | 明确不进入出库单，必须填写原因 |

右侧预览必须显示 Traveler 中读取到的全部材料，包括已映射、未映射、已忽略和数量为 0 的项目。
未映射项目使用醒目颜色高亮，并阻止进入库存系统。用户可以在预览中选中一种或多种材料，
点击“忽略选中材料”；该选择保存在本机商品映射中，以后同名材料继续忽略。已忽略项目灰色显示，
可以选中后点击“恢复选中材料”。本地同步记录仍保存名称、数量和忽略原因。

更新商品资料后重新校验人工映射：

- 商品仍存在且启用：继续使用。
- 商品不存在、停用或明显变化：映射失效并提醒。
- 不自动将失效映射改到其他商品。

Traveler 未变化时，不因为商品映射文件单独变化而更新已出库单。以后 Traveler 本身发生有效变化时，使用当时最新映射。

### 6.2 网页查询

1. 先在本地通过 Traveler 名称、类别、规格和规则得到商品编号。
2. 网页端统一使用商品编号精确查询。
3. 查不到：停止。
4. 查到多个候选：停止并列出候选。
5. 唯一结果但已停用或不可选择：停止。
6. 不直接用模糊商品名称在网页中盲选。

### 6.3 已确认的特殊规则

| Traveler 名称 | 库存处理 |
| --- | --- |
| `Adjustable shelf holder` | `M1013 — Shelf Holder` |
| `Shelf Holder` | `M1013 — Shelf Holder` |
| `Hinge` | `M1001 — Unihopper Hinge` |
| `H-Rail` | `M1002 — H-Rail` |
| `L-Rail` | `M1003 — L-Rail` |
| `M.C(L)` | `M1089 — M.C(L)` |
| `TB18` | `M1014 — 15寸垃圾桶(TB18用)` |
| `TB15`、`TB21` 等 | 查找名称中包含对应 `TB型号用` 的垃圾桶；零结果或多结果停止 |
| `Push Open × N` | 拆成 `M1068 × N` 和 `M1069 × N` 两行 |

Plywood 只使用 Finished：

| Traveler 厚度 | 库存商品 |
| --- | --- |
| `18mm` | `3/4 Finished, UV2S` |
| `14.5mm` | `5/8 Finished, UV2S` |
| `5.4mm` | `1/4 Finished, UV1S` |

14.5/15mm 和 5.4/5.2mm 的规格差异属于已确认别名。

Panel 按类别、颜色名称和厚度规格匹配。封边先按 Edge band 类别和“颜色 + Edge Banding”精确名称匹配；
没有精确名称时，按同颜色、名称包含“ABS banding”且名称以“24mm”结尾的商品匹配。
仍不唯一或找不到时必须人工处理，不得根据相似名称猜测。
背板 Panel 的8mm和9mm视为双向等价厚度：Traveler写8mm可以匹配库存9mm，
Traveler写9mm也可以匹配库存8mm；仍须同时满足Panel类别和颜色名称，19.1mm门板不参与该等价规则。
固定业务规则均未命中后，允许用 Traveler 材料名称与库存商品名称做完全一致匹配；
只有唯一一条结果时才采用。BLS36 因此对应唯一商品 M1093，不使用模糊搜索。
未映射材料可以在右侧选中后点击“设置映射”。程序允许按商品编号、名称、规格、类别或备注
搜索本机商品资料，只显示启用商品；用户确认商品后将映射保存到本机 mappings.json，
取消该材料原有忽略状态，并自动重新预检当前 Traveler。

## 7. 出库预览与人工确认

网页打开前显示：

- 工厂单名称。
- Traveler 文件和修改时间。
- 商品编号。
- Traveler 原名称。
- 库存商品名称。
- 数量。
- 匹配来源。
- 零数量跳过项。
- 已忽略项目和原因。
- 异常和冲突。
- 当前商品资料更新时间及商品数量。

所有本地检查通过后，由用户点击“确认写入库存系统”才打开浏览器。

从预览到确认写入之间再次校验：

- Traveler 文件指纹发生变化：取消并重新预览。
- 当前预览使用的商品映射发生变化：取消并重新预览。

## 8. 登录与浏览器

- 使用可见浏览器，用户可以观察全过程。
- 自动登录金蝶并优先复用本地浏览器登录状态。
- 用户名保存在本机设置；密码只保存到 macOS 钥匙串。
- 用户名、密码、真实商品资料和真实映射不写入日志或 GitHub。
- 登录失败后约 30 秒、60 秒重试，共三次；仍失败则停止并提醒。
- 遇到验证码、短信、扫码等人工验证时暂停，由用户手工完成后继续。
- 登录后若出现多个“进入使用”按钮，视为故障，停止并提醒，不保存账套配置。
- 网页按钮名称、表格列或布局变化时停止，保存截图和步骤信息，不按相似位置盲点。

## 9. 新建其他出库单

网页流程：

1. 登录 `https://www.jdy.com/login/`。
2. 点击右侧唯一的“进入使用”。
3. 点击左侧“仓库”。
4. 点击弹出菜单中的“其他出库单”。
5. 鼠标立即移动到页面上方或菜单外空白区域。
6. 等待悬浮菜单收起和新增出库单界面完整显示。
7. 如果未显示，重复一次移开鼠标并等待；仍失败则停止。
8. 业务类型选择“生产领料”。
9. 备注填写正式工厂单名称组合。
10. 其他字段保留系统默认值。
11. 按 Pickinglist 顺序用商品编号查询并选择商品。
12. 只填写数量，不修改系统带出的计量单位。
13. 行数不足时点击左侧数字列中的加号增加行。
14. 等待用户最终确认后才允许点击保存。

## 10. 单据编号重复

- 自动改号只适用于新建单据。
- 保存提示“单据编号重复”时，从最右侧数字开始加 1。
- 最多尝试 10 次。
- 第 10 次仍重复则停止，显示初始编号、最终编号和失败信息。
- 修改已有单据时必须保留原编号；若仍提示重复，停止并提醒，不能改号。

## 11. 保存、回查与不确定结果

只有同时满足以下条件才记录成功：

1. 网页明确显示保存成功。
2. 在记录页面能重新查询到同一张单据。

保存后同时按单据编号和工厂单名称查询：

| 查询结果 | 处理 |
| --- | --- |
| 两种查询指向同一记录 | 确认成功 |
| 编号查到但名称不一致 | 冲突，停止 |
| 名称查到但编号不同 | 停止并列出记录 |
| 名称查到多张 | 停止并列出全部 |
| 两种都查不到 | 标记未保存，不自动重试 |
| 查询失败 | 标记“保存结果未知” |

如果点击保存后网络中断或页面卡住，必须先执行上述双重查询，不能直接再次保存。

## 12. 已有出库单更新

### 12.1 查找原单据

`仓库 → 其他出库单右侧“记录” → 输入单据号 → 查询 → 双击记录`

本地同步记录丢失时，新建前先按工厂单名称查询：

- 找到一张：由用户选择关联现有单据或取消。
- 找到多张：停止并列出。
- 找不到：才允许新建。

### 12.2 整单同步

Traveler 有效内容变化时，修改原出库单：

- 新增材料：增加商品行。
- 数量变化：更新数量。
- 已删除材料：删除原商品行。
- 备注变化：更新为最新正式工厂单名称。
- 最终商品表必须与最新 Traveler 完全一致。
- 不使用补差单。

原单据已审核、锁定或不可编辑时停止，不反审核、不删除、不新建替代单，显示状态和差异供人工判断。

仅文件修改时间或格式变化、实际出库内容未变化时，不打开库存系统，只更新本地检查时间和文件指纹。

## 13. 库存不足和网页警告

- 库存不足、负库存、批次缺失或其他库存警告时暂停。
- 显示商品编号、商品名称、需求数量和网页提示。
- 提供“取消本次出库”“返回处理”“仍然强制保存”。
- 强制保存必须由用户明确点击，并记录人工授权和网页警告。
- 每一次新的警告都必须再次人工确认，授权不自动延续。

## 14. 状态记录

状态定义：

| 状态 | 含义 |
| --- | --- |
| 未出库 | 没有成功记录 |
| 已出库 | 当前有效内容与最后成功同步一致 |
| 需要更新 | 已出库，但 Traveler 有效内容发生变化 |
| 处理中 | 当前正在执行网页操作 |
| 失败 | 已明确失败，可安全重试 |
| 结果未知 | 保存或查询结果无法确认，必须人工核实 |
| 原单据不可编辑 | 已审核、锁定或其他状态阻止修改 |

库存任务是人工启动且影响真实库存，因此每次运行发现异常都显示，不采用“仅首次出现或变化时提醒”。

本地记录保存：

- Traveler 完整路径。
- 文件修改时间和内容指纹。
- 工厂单名称组合。
- 出库单编号。
- 单据链接或内部 ID（如网页可取得）。
- 商品和数量快照。
- 忽略项目及原因。
- 最后同步时间、结果和人工授权。

记录建议保存在：

`~/Library/Application Support/工作流程助手/inventory-sync.json`

每次成功创建或更新后，在覆盖记录前备份旧记录；只保留最近 50 份。该轮换不属于已取消的“月底清理三个月前备份”任务。

## 15. 安全与 GitHub

以下内容不得上传 GitHub：

- 金蝶用户名和密码。
- AIMES 用户名和密码。
- 浏览器会话数据。
- 真实商品导出 Excel。
- 真实商品编号映射。
- 库存同步记录。
- 含库存、采购价或订单信息的运行日志和截图。

GitHub 只保留：

- 不含真实编号和库存数据的示例文件。
- 业务规则文档。
- 程序代码和自动化测试。

安全测试必须检查真实凭据、商品资料和本地同步文件没有进入 Git。
