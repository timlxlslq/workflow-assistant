# 订单看板界面与操作原型规格

状态：待用户审核，尚未进入实现。

本文件只规定界面、信息层级和操作流程，不包含 Swift、Python、WeCom 或 CNC 实现方案。

## 1. 目标

用户打开 App 后，可以最快回答五个问题：

1. 当前有哪些订单？
2. 每个订单拆成了哪些工厂单？
3. 哪些工厂单已优化，哪些真实生产状态仍未知？
4. 每个订单用了什么材料，库存是否足够？
5. 哪些工厂单已经出库，订单是未出货、部分出货还是已出货？

## 2. 页面结构

订单统计卡片显示在“助手”页，订单看板主体继续保留独立的“订单中心”入口：

`助手 | 订单中心 | 待办 | 设置`

- “助手”页顶部只显示 8 张订单统计卡片，不迁入搜索、筛选、同步按钮、操作记录或订单表格。
- “订单中心”负责筛选、订单/工厂单详情和进入操作。
- 生产文件保留 material/Traveler 的读取、校验、生成和更新能力，作为订单中心的上下文操作入口。
- 出库保留库存预检、人工确认和真实出库能力，作为订单中心的上下文操作入口。
- “待办”保持独立，不与订单状态自动关联。
- 页面继续使用当前 App 的默认窗口大小与最小尺寸约束，不修改 `defaultSize`、`windowIdealWidth`、`windowIdealHeight`、`windowMinWidth` 或 `windowMinHeight`。

## 3. 订单看板

### 3.1 顶部筛选区

第一行使用可点击摘要卡：

- 全部订单
- 已设计
- 已拆单待优化
- 已优化
- 库存不足
- 部分出货
- 已出货
- 数据异常

点击摘要卡只改变下方订单列表筛选，不直接执行网络查询或文件写入。

第二行包含：

- 搜索：订单号、工厂单号、工厂单名称、房间名称。
- 状态筛选。
- 排序：最近变化、订单号、出货进度、库存风险。
- “刷新数据”按钮。

### 3.2 订单列表

每个订单占一行，建议列为：

| 列 | 显示内容 |
|---|---|
| 展开 | 展开/收起工厂单 |
| 订单 | 订单号与订单类型 |
| 状态 | 已设计、已拆单待优化、已优化、部分出货、已出货 |
| 工厂单 | 工厂单总数 |
| 优化进度 | `已优化数量/工厂单总数` |
| 材料 | 板材、封边条、五金摘要 |
| 库存 | 未查询、充足、不足、失败 |
| 出货进度 | `已出库工厂单数/工厂单总数` |
| 更新时间 | 最近一次内容变化或同步时间 |
| 操作 | 查看详情、生产文件、查询库存、创建出库 |

订单的“阶段”用于快速浏览，但不能隐藏各维度事实；例如订单可以同时是“已优化”“库存不足”“部分出货”。

### 3.3 展开的工厂单

点击订单行展开箭头，在该行下方显示工厂单，不打开新窗口：

| 列 | 显示内容 |
|---|---|
| 工厂单 | AIMES 工厂单号 |
| 名称/房间 | 工厂单名称及匹配房间 |
| 拆单 | 已拆单/异常 |
| 优化 | 已优化/待优化/待人工匹配 |
| 真实生产 | 当前版本固定为“未接入”或“待确认” |
| 板材/封边 | 有用量/无用量/待确认 |
| 五金 | 有用量/无五金/待确认 |
| 库存 | 充足/不足/未查询/失败 |
| 出库 | 未出库/已出库/需要更新 |

客户变更后新增的工厂单按普通独立行显示，不添加“替代”“旧版本”或“作废”标签。

### 3.4 已出货状态回退示例

PP0067 原有两个工厂单均已出库时显示“已出货，2/2”。AIMES 后续返回第三个不同名称的新工厂单后：

- 订单改为“部分出货”。
- 出货进度改为 `2/3`。
- 新工厂单显示“未出库”。
- 历史两个工厂单的出库记录保持不变。
- 操作记录新增：“发现新增工厂单，订单状态由已出货调整为部分出货”。

## 4. 订单详情

点击订单号或“查看详情”打开详情页或右侧详情抽屉。默认窗口较宽时优先使用右侧详情；窗口不足时进入完整详情页，不能压缩主表导致文字和按钮互相遮挡。

### 4.1 展开详情

- 展开后不显示重复的订单号/状态、摘要卡、“订单详情”标题或页签切换条。
- 默认直接显示工厂单表格，表格只展示工厂单号、名称、拆单、优化、出库和 Panel 颜色。
- Panel 数量属于订单级总量，不在工厂单行中拆分显示。
- Traveler、库存查询和出库通过顶部上下文操作按钮进入既有流程；材料和文件详情继续由既有生产文件流程承载。

## 5. 操作反馈

- 当前正在执行的动作显示在内容区固定状态条，例如旋转图标加“正在查询材料库存…”。
- 顶部导航不显示重复操作状态。
- 操作记录保存历史成功、失败、警告和状态回退原因。
- 库存查询失败后，“查询库存”恢复可点击，允许再次查询。
- 生产文件预检失败或 Traveler 打开校验失败，不阻止“更新 Traveler”。
- Dashboard 初次出现时先显示最近汇总结果，不因自动启动多个浏览器任务导致界面长时间不可操作。

## 6. 复用约束

后续实现优先复用：

- `TopNavigationBar` 和 `AppSection`。
- `AppLayout` 与 `AppPalette`。
- `AppSurfaceCard`、`AppStatusBadge`、`OperationLogCard`。
- `OrderFolderItem`、`OrderMaterialPreview`、`OrderFactoryPreview`、`OrderFittingPreview`、`OrderStockPreview`。
- 生产文件页已有订单预览、Traveler 按钮和库存查询入口。
- 出库页已有库存比较、确认和出库操作。

订单中心只新增汇总模型、订单/工厂单状态展示和带上下文跳转；不得复制一套生产文件或出库业务逻辑。

## 7. 本版本不包含

- WeCom `Order Management` API 同步或迁移。
- CNC/KDT 机器 API、加工记录或生产状态采集。
- 根据文件夹自动判定真实生产完成。
- 待办与订单业务状态的自动联动。
- 修改 App 默认窗口尺寸。

## 8. 原型审核重点

用户审核时重点确认：

1. 一屏内订单摘要是否足够清楚。
2. 展开工厂单后是否能快速识别新增、未优化、库存不足和未出库项。
3. PP0067 从“已出货”回到“部分出货”的原因是否容易理解。
4. 生产文件、库存查询和出库入口是否放在符合实际操作顺序的位置。
5. 展开详情是否足够简洁，顶部操作按钮是否能覆盖 Traveler、库存和出库的主要入口。
